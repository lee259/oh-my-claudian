# Antigravity constraints

## Session creation and recovery

- Authentication is native: never call ACP `authenticate` or store Google credentials. Auth failures point to `agy acp --login`.
- Never fall back from `session/resume` to `session/load`: agy answers load for any id, then fails the next prompt (`trajectory not found`). A missing-session error keeps the binding; `historySessionId` locators written by earlier versions stay readable because transcripts outlive the session database. A failed immediate resume after creation keeps the new native id for retry.
- The native store follows HOME (USERPROFILE on Windows); launch changes, including a moved store, keep bindings and reload them.
- Main chat runs on agy's default agent, so its persona, guidelines, vault rule files and tool set (including subagents) stay. Claudian's prompt goes only in `session/resume` `_meta.antigravity.systemPrompt.append`: agy stores a `session/new` append permanently and stacks later appends on it, while a resume append is not stored and each one replaces the last. Every resume therefore sends the current prompt, and a changed prompt re-resumes the open session before the next turn.
- Auxiliary sessions (title, Inline Edit) need tool restriction, which only custom agents provide (agy ignores `disableBuiltInTools` on its default agent). Their agent body and tools are frozen at native session creation; select and prepare agent files only for `session/new`, never send them an append, and resume existing ids without file checks or agent selection.
- A newly created auxiliary session is already ready when it has no native MCP setup: do not resume it again. Main chat still resumes so the current system-prompt append is delivered, and any session with MCP servers resumes to install them. Publish the created id before resume; mark it loaded only after preparation succeeds so failures can retry the same id. Claudian does not expose its session-tool MCP server to agy; every request carries only explicitly configured native MCP servers.
- Claudian owns only marked generated `agent.md` files, not their directories. Refuse foreign or malformed files; file failures must prevent native creation rather than silently use agy's default agent.
- Off because agy's ACP server lacks them: fork, rewind, ephemeral sessions, fast mode.

## Models and discovery

- Discover the picker catalog with the standalone `agy models` command; never create a promptless ACP session just to list models. A live session report is authoritative over standalone discovery, including when a slower standalone probe finishes later or fails. Apply model, `thought_level` and mode with `session/set_config_option` only when they differ, and retire the process when cancellation interrupts that step so the cached values cannot go stale. `thought_level` is reported only for the current model and is absent for fixed-effort models; send none when the session offers none. Per-model levels come from the legacy session model list or the standalone variant list.
- The prompt-less discovery probe is only for ACP commands and is unlisted, but it can still leave a native session directory.
- Unsupported built-in commands are hidden by name (`ANTIGRAVITY_HIDDEN_COMMANDS`) because agy marks no command as built-in.

## Permissions and tools

- agy relays subagent and workflow-agent approval requests and `ask_question` forms on the parent session, with tool call ids prefixed by the subagent's id (`<subagent>:call_…`); only a subagent's calls that ask reach ACP. YOLO runs native `default` and approves every request client-side. Do not launch agy with `--dangerously-skip-permissions`: it applies to the whole process until restart, so switching YOLO would replace the process. Auxiliary sessions' read-only and passive policies depend on Claudian denying requests. Never select native `plan`; Claudian has no plan mode.
- Auxiliary agent files exclude subagent tools (built-in subagents are unavailable under a custom agent, upstream #1225). Main chat cannot exclude them; they report after `end_turn`, and agy's reply to each report streams in a background turn.
- Inline Edit is read-only by tool set (`read_file` and `search_web`) as well as prompt; it does not receive `run_command`.
- `ask_question` arrives as form `elicitation/create` only when the client advertises elicitation; answer with option `const` values (match them before labels) and free text in `<field>_other`. Its completed update omits the answers, so the question router supplies them to the tool result by tool call id.
- agy can report licence, subscription, and location-eligibility failures as ordinary assistant text. Treat those messages as access failures, invalidate the session, and never render them as a normal answer.

## Streaming and history

- Claudian supports only current agy (the settings tell users to keep it updated). agy echoes no prompt or steer and replays nothing it did between turns, so Claudian emits every user boundary itself. A steer is confirmed when agy answers the prompt it takes over, or when the turn completes.
- agy streams what it does on its own after `end_turn` (its reply to a subagent's report or a finished background command, with tool calls and approval requests) live on the session, with no echo, start or end. Main chat shows it as one background turn, closed once nothing follows a `usage_update` for a second (agy ends every model call with one and streams that call's tools within milliseconds) or at the failure of a call Claudian did not approve; closing early only splits the reply. A run holds its prompt until that turn closes: agy finishes its own reply, including a pending approval, before answering, and a fast answer would otherwise join the reply. Without a closing usage update, two quiet minutes release the next prompt once there are no outstanding tools or client requests. Between runs, approvals, questions and Obsidian workspace tools follow the policy of the latest run whose prompt reached agy, also while a newer run waits for the reply, and fail closed; auxiliary sessions get no background turn and keep denying. `session/cancel` also stops agy's background tasks and subagents, and after a Stop between runs agy reports the calls it ended as `tool_call_update`s, which must not open a turn. A prompt agy answers counts as received even when cancelled before any output. An update for a call the turn has not seen (a background command an earlier turn launched) is shown as that call.
- agy reports no subagent lifecycle over ACP. While a main-chat subagent is outstanding between turns, `AntigravitySubagentWatcher` reads the transcript (a report is a `SYSTEM_MESSAGE` whose sender is the subagent's `conversationId`) and holds idle release until every subagent has reported or its matching native child record confirms `SUBAGENT_STATE_KILLED`, then until agy's reply to the last report starts, or 30 minutes pass without a transcript change; where the directory cannot be watched, a poll counts only a changed revision of either transcript file. The watcher's report-only history change is recognized as agy's own write so the pre-send guard does not cool the process before its reply. A subagent outstanding when agy's process ends did not run after resume (probe 19), so ending a process stops watching and only subagents created from that process's first recorded request count; that request is read at the first successful transcript read after a turn's prompt settles. A steer after the first launch in a process can end watching early (accepted).

- A prompt response's usage sums every model call in the turn; never use it as context. The context meter shows the turn's latest `usage_update` (`used`/`size`) as reported, even though agy compacts Gemini at 256,000 tokens. A `/compact` turn's report still measures the old context, so that turn reports none; a turn without a report hides the meter.
- agy reports compaction only as a transcript `CHECKPOINT`: live, a `/compact` prompt that completes (not a steer that took over) is the boundary. Transcript `SYSTEM_MESSAGE`s from a task sender are notifications; `sender=system` notices are only context.
- Transcripts have no cancellation or steer marker. On replay, trailing unfinished model/tool output carries `isInterrupt` and no completion timing; a final planner reply without tools, a completed checkpoint, or a terminal `permission check failed` result completes it (denial also completes live). `USER_INPUT` may be a steer and task reports may arrive mid-run, so neither boundary proves an interruption. Empty/system-only segments do not prove a stop; a trailing incomplete snapshot cannot distinguish cancellation from another client's running turn. Background launch `RUNNING` status is not a turn outcome.
