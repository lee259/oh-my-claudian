## Highlights

- **Skills live in one place.** Shared skills can be browsed and inspected from a single settings library, and Claude commands or skills under `.claude/skills` and `.claude/commands` can be copied into it after an explicit preview. Linked skill folders resolve correctly, and every provider now reads the same skill list.
- **Model choices stick.** Claude uses the shared model picker, Cursor and OMP alias selections survive reopening settings, DeepSeek keeps its configured model order, and OpenCode offers turn steering only when the native session supports it.
- **Vault writes resist corruption.** File writes land atomically, existing file modes are preserved, locked replacements retry instead of failing, and settings fall back to their last committed values when a save fails.
- **Long conversations stay responsive.** Stored transcripts render in windows, collapsed reasoning and mention recency are prepared lazily, and menus, keyboard focus, header actions, and async question folding stay stable while the chat updates.

Claude skill migration is opt-in and requires confirmation per skill. Provider features and permissions remain capability-specific, and no data migration is required.
